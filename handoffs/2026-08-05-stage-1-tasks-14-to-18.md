## Decisions already made — do not relitigate

- **The user asked for full rigour through the remaining tasks**, at the 14/19 mark, after ~10h of
  agent time and with the option to go lighter or stop. They chose to keep the same process. Honour
  that; do not quietly downgrade to single-pass reviews.
- **The machine is decomposed**, not one seven-state table: a link machine, a suppression latch, and
  one controller per half, with the spec's seven reported state names derived by a pure projection.
- **`IsConnected` is split**: `IAudioSinkService.IsConnected` reports only that the WinRT connection
  object is open. Endpoint presence belongs to `IAudioEndpointMonitor`. They are separated by an
  unbounded interval and folding them makes that interval unrepresentable.
- **The calls half's health is `IsRegistered()`**, never `PhoneLineTransportDevice.ConnectAsync`'s
  bool, which returns `False` on every run of this machine including ones where calls demonstrably
  work.
- **`Unknown` link status counts as `Disconnected`**, and a **poll** must report non-`Connected`
  twice consecutively before `Present` becomes `Absent` (Task 19). Watcher edges stay immediate.
- **Everything is single-threaded on the UI thread** via the existing `IUiDispatcher`. No locks in
  `ConnectionManager`.

## Next steps

### 1. Task 14 — `MusicHalf`

Carry into the dispatch:

- **`AudioRouter.Start()` can return `true` for a route that died inside `StartRecording`.** The plan
  anticipated this ("retry logic that trusts the return value will loop") and the route backoff is
  the answer. **Do not** change `AudioRouter.cs:187` to `return IsRunning;` — a reviewer confirmed
  all 19 router tests stay green either way, so it would be exactly the unpinned change the standing
  rule forbids. `MusicHalf` should treat the bool as advisory and drive off `IsRunning` / `Stopped`.
- The two transitions that close the reconnect gap: `Up` + `router.Stopped` → `Linked` with **no**
  Bluetooth reconnect (a call invalidates the endpoint without closing the connection), and `Linked`
  + endpoint present → `router.Start(outputId)`.
- `Linked` **never times out**. It is the normal state whenever the phone is not streaming.

### 2. Task 15 — `CallsHalf`

- There is deliberately **no `OnLinkAbsent`**. Registration is not link-scoped; unregistering on
  every range exit would flap the phone's call-audio-device option. The absence of the method is what
  makes the rule structural. The brief has a reflection test asserting the method does not exist.
- `Registered == true` with `TransportConnected == false` is **success**. That is the single most
  important test in the task.

### 3. Task 16 — `ConnectionManager` (the big one)

It inherits five constraints the plan never anticipated, all found by reviews:

1. **The endpoint presence probe costs 152-282 ms per read** and MMDevAPI **duplicates**
   notifications. A consumer that reads the level per `EndpointsChanged` pays N × that per burst —
   seconds of frozen message loop. Run the enumeration **off the UI thread** and post only the
   resulting bool through `IUiDispatcher`; treat `EndpointsChanged` as **"mark dirty"**, never "go
   look"; read the property once per reconcile pass into a local.
2. **`ICallTransportService.IsRegistered` is an unguarded live CsWinRT ABI call** and the reconcile
   loop will read it on a 30 s timer, where a throw propagates out of the timer callback to
   `Application.ThreadException`. The likely answer is a tri-state read
   (`Registered`/`NotRegistered`/`Unknown`) that a fake can return `Unknown` from, keeping `bool
   IsRegistered` as the tray menu's convenience. The standing rule forbids an untestable catch.
3. **The projection consults the suppression latch but not `settings.AutoReconnect`**, so between the
   latch clearing and the next drop re-setting it, the tray can report `Discovering`/`RetryBackoff`
   while connect-permitted is false and nothing will be attempted. Consider a ninth snapshot field.
4. **`ConnectionSnapshot` carries only bools for the halves**, so the detail text cannot say *why*
   calls are off — setting versus no MSIX identity. Pass `CallsAvailability` through if the tray
   should name package identity.
5. **Where `PowerNotifier.Start()` is wired determines the callback thread.** `SystemEvents` captures
   the *subscribing* thread's `SynchronizationContext` and dispatches via `Send` (blocking). Post
   through `IUiDispatcher` regardless, because the contract is order-dependent.

Also flag for its review: `ConnectionState.cs:269-271` — `DegradedDetail`'s calls branch is the one
read in that file without an `Enabled` guard. Unreachable today (proved), but it is the line that
starts printing "calls retrying in 8s" for a half the user switched off if a projection rule is ever
widened again, and Task 16 may widen one.

Three questions only the hardware test can answer, all already written up as things it must record:

- Whether music returns unattended after a call ends. The design assumes the A2DP connection survives
  a call — confirmed only for the first 30 s of one call, because that is where the log ends.
- **Which notification callback actually carries the A2DP endpoint's arrival.** Deliberately
  unmeasured; the endpoint monitor admits all three existence callbacks rather than guessing. Record
  the endpoint's **name** at the moment of arrival too, not only which callback fired — presence is a
  friendly-name match and a rename arrives on a callback the class deliberately rejects.
- **How large the notification bursts really are.** The Task 1 probe's 40-callback census was entirely
  `OnDefaultDeviceChanged`, which this class filters out, so `OnDeviceStateChanged` volume has never
  been measured. Both the UI-thread cost and the logging-volume bound currently rest on that gap.

Also expect `Call transport registration succeeded.` followed by
`Call transport reported TransportConnected=False.` — the wording changed in Task 10.

## Gotchas that have already cost time

- **`git checkout -- <dir>` destroyed uncommitted work for three separate implementers.** Tell every
  implementer to use `git stash` or verify with `git diff --stat` before and after a mutation sweep.
- **Restoring a mutated file with `Copy-Item` preserves the source's older `LastWriteTime`**, so
  MSBuild skips the recompile and the test DLL keeps the previous mutant — the suite goes red against
  correct source, and `git diff --stat` cannot see it. Force the timestamp and run a green control
  after every restore.
- **`System.Windows.Forms.LinkState` collides with `Klangbruecke.Connection.LinkState`.** Both
  projects set `UseWindowsForms` + `ImplicitUsings`, so any file *outside* namespace
  `Klangbruecke.Connection` naming `LinkState` unqualified gets `CS0104`. Production files are fine;
  test files need `using LinkState = Klangbruecke.Connection.LinkState;`. Do not rename the enum.
- **`dotnet run` is not a dev loop for the music half.** `AudioPlaybackConnection.TryCreateFromId`
  kills an unpackaged process with an uncatchable `AccessViolationException`. `AudioSinkPolicy` gates
  it in two places — **do not remove either** "to let it try".
- **Do not implement LAF token generation.** Standing project instruction, the user's call.
- Reports go in the gitignored workspace, so they are never committed. That is intentional.
